## 1. 🎯 Суть и цель
Создание эшелонированной защиты на границе приложения. Цель — гарантировать, что до бизнес-логики (бэкенда) дойдет только валидный и безопасный трафик. Обратный прокси скрывает реальные IP-адреса серверов, WAF отсекает попытки инъекций, а IDS фиксирует подозрительные сетевые паттерны для последующего разбора в SIEM.

## 2. 📚 Что изучить (Теория)

| Тема | Конкретные вопросы для изучения |
| :--- | :--- |
| **Архитектура Reverse Proxy** | • Разница между прямым (Forward) и обратным (Reverse) прокси.<br>• Понятие терминирования TLS: почему расшифровка трафика происходит на прокси, а бэкенд получает обычный HTTP (или зашифрованный mTLS).<br>• Важность заголовков `X-Forwarded-For` и `X-Real-IP` для корректного логирования IP клиента. |
| **Принципы работы WAF** | • Сигнатурный анализ (поиск известных паттернов, например `UNION SELECT`) против поведенческого анализа.<br>• Режимы работы: Detection (только логирование, Pass) и Prevention (блокировка, Drop).<br>• Проблемы ложных срабатываний (False Positives) и необходимость тонкой настройки правил (Whitelisting). |
| **IDS/IPS в современных сетях** | • Почему классические сетевые IDS (Suricata) сложнее применять в зашифрованном трафике (TLS 1.3) и как это решается (терминирование на прокси или использование eBPF). |

## 3. 💻 Практическая задача (Лабораторная работа)

**Название:** Развертывание Nginx Reverse Proxy с кастомным WAF и самоподписанным TLS  
**Инструменты:** Хост-машина (Ansible), ВМ-1 (Ubuntu-Server).

**Пошаговое выполнение:**
1. **Подготовка бэкенда:** Создайте на хосте файл `backend.conf` (простой конфиг Nginx, слушающий 8080 порт и отдающий тестовую страницу). Добавьте его в Ansible-роль или задачу копирования.
2. **Создание WAF-правил:** Создайте файл `waf.rules` для Nginx:
   ```nginx
   # Блокировка базовых SQL-инъекций и XSS в URI и аргументах
   set $block_sql_injections 0;
   if ($query_string ~* "union\s+select") { set $block_sql_injections 1; }
   if ($query_string ~* "select\s+.*\s+from") { set $block_sql_injections 1; }
   
   set $block_xss 0;
   if ($query_string ~* "<script>") { set $block_xss 1; }
   if ($query_string ~* "javascript:") { set $block_xss 1; }
   
   if ($block_sql_injections = 1) { return 403 "WAF: SQL Injection blocked\n"; }
   if ($block_xss = 1) { return 403 "WAF: XSS blocked\n"; }
   ```
3. **Конфигурация Reverse Proxy:** Создайте файл `proxy.conf`:
   ```nginx
   server {
       listen 443 ssl;
       server_name lab.local;
       
       # TLS сертификаты (сгенерируйте их через openssl и скопируйте через Ansible)
       ssl_certificate /etc/nginx/ssl/cert.pem;
       ssl_certificate_key /etc/nginx/ssl/key.pem;
       
       # Подключение WAF правил
       include /etc/nginx/waf.rules;
       
       location / {
           proxy_pass http://127.0.0.1:8080;
           proxy_set_header Host $host;
           proxy_set_header X-Real-IP $remote_addr;
           proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
           proxy_set_header X-Forwarded-Proto $scheme;
       }
   }
   ```
4. **Обновление Ansible Playbook:** Добавьте задачи для генерации сертификатов (или копирования готовых), копирования конфигов (`backend.conf`, `proxy.conf`, `waf.rules`) в `/etc/nginx/`, установки Nginx и перезапуска службы.
5. **Применение:** Запустите `ansible-playbook -i inventory.ini site.yml`.

## 4. ✅ Критерий успеха

| Проверка | Команда для терминала | Ожидаемый результат (Критерий успеха) |
| :--- | :--- | :--- |
| **Штатный доступ по HTTPS** | `curl -k https://192.168.56.10/` | Возвращает `200 OK` и HTML-код страницы бэкенда. Флаг `-k` игнорирует предупреждение о самоподписанном сертификате. |
| **Блокировка SQL-инъекции** | `curl -k "https://192.168.56.10/?id=1 UNION SELECT password FROM users"` | Возвращает `403 Forbidden` и текст "WAF: SQL Injection blocked". |
| **Блокировка XSS** | `curl -k "https://192.168.56.10/?q=<script>alert(1)</script>"` | Возвращает `403 Forbidden` и текст "WAF: XSS blocked". |
| **Скрытие бэкенда** | `curl -I -k https://192.168.56.10/` | В заголовках ответа нет упоминания порта 8080 или внутренних IP. Заголовок `Server` показывает только Nginx (без версии). |
